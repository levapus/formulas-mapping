## Что это?

Исходный документ `Formulas.doc` содержит таблицы продуктов и условий:

| Колонка в Word | Смысл в приложении |
|----------------|--------------------|
| Колонка 1 | Название продукта |
| Колонка 2 | Условия, когда продукт **рекомендуется** |
| Колонка 3 | Условия, когда продукт **не рекомендуется** (избегать) |

Инструмент превращает таблицы в данные и браузерный интерфейс:

1. Выберите **категорию** (по желанию).
2. Выберите условия в блоках **Рекомендуется** (зелёный) и/или **Не рекомендуется** (красный).
3. Смотрите таблицу результатов с галочками recommend / avoid / нейтрально.
4. При необходимости экспортируйте видимую таблицу в Excel (`.xlsx`).

Правила:

- Если продукт и рекомендуется, и не рекомендуется при выбранных условиях, побеждает **не рекомендуется**.
- Без ИИ и без обязательной сети: статический HTML/JS + `data/data.json`.

Связанные файлы:

| Путь | Роль |
|------|------|
| `Formulas.doc` | Исходный Word (по желанию; свой экземпляр для повторного импорта) |
| `data/data.csv` | Редактируемый источник истины |
| `data/data.json` | Сгенерированный каталог для UI (**не править вручную**) |
| `web/` | Статический интерфейс |
| `scripts/` | Импорт, CSV, сборка каталога |

## Как установить

**Требования**

| Нужно | Для чего |
|-------|----------|
| Python 3.12+ | Импорт, сборка JSON, pytest |
| Windows + Microsoft Word | **Только** для импорта `Formulas.doc` (`pywin32` / COM) |
| Node.js 18+ | По желанию: JS-тесты |
| Современный браузер | Интерфейс |

Из корня репозитория:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
```

`requirements.txt` ставит `pytest` и (только на Windows) `pywin32`.

Без Word можно править CSV, собирать JSON, запускать UI и тесты.

## Как запустить

Все команды ниже — **из корня репозитория**.

### С локальным сервером (Python)

```bash
python -m http.server 8080
```

Откройте [http://localhost:8080/web/](http://localhost:8080/web/).

Страница сама загружает `../data/data.json`. Сервер нужно запускать из **корня репозитория**, не из `web/`.

### Без Python / без сервера

1. Откройте `web/index.html` двойным щелчком (или в браузере).
2. В левой панели нажмите **Загрузить данные** и выберите `data/data.json`.

Браузеры блокируют автоматический `fetch` на `file://`, поэтому нужен ручной выбор файла. После успешной загрузки в статусе появится число условий/продуктов, заполнится список категорий.

Подойдёт и любой другой статический сервер (Node `npx serve`, IIS, nginx и т.д.) с корнем на репозиторий, затем `/web/`.

## Процесс: Word → CSV → JSON

```text
Formulas.doc  ──(import_formulas)──►  data/data.csv  ──(build_json)──►  data/data.json  ──►  web UI
     Word COM                         редактируемые строки              каталог для UI
```

1. **Word (`Formulas.doc`)**  
   Таблицы: первая ячейка заголовка = категория; строки данных = продукт + текст «рекомендуется» + текст «не рекомендуется».

2. **Импорт (`python -m scripts.import_formulas`)**  
   Читает таблицы через Word COM, делит ячейки условий, пишет в `data/data.csv` по одной строке на связь продукт–условие–полярность.

3. **Сборка (`python -m scripts.build_json`)**  
   Читает CSV, нормализует ключи, сливает синонимы (`canonical_key`), убирает дубликаты, пишет `data/data.json`.

4. **UI (`web/`)**  
   Загружает JSON, фильтрует по категории и условиям, показывает таблицу, экспортирует Excel.

Повседневные правки обычно без Word: меняете CSV, затем только `build_json`.

## Как импортировать из Word

Нужны **Windows + Microsoft Word**. Word запускается скрыто; документ открывается только для чтения.

```bash
python -m scripts.import_formulas --doc Formulas.doc --out data/data.csv
python -m scripts.build_json
```

- `--doc` по умолчанию `Formulas.doc`, `--out` — `data/data.csv`.
- Импорт **полностью перезаписывает** `data/data.csv`.
- Затем `build_json` пишет `data/data.json` и выводит число условий.
- После успешного обновления закоммитьте оба файла: `data/data.csv` и `data/data.json`.

Как делятся ячейки:

- Условия делятся **только** по нумерации (`1.`, `2)`) или, если нумерации нет, по переводам строк.
- Запятые **никогда** не используются как разделитель.
- Имена продуктов автоматически не дробятся.

**Чеклист полного обновления из Word**

1. Сохраните ручные правки CSV (`copy data\data.csv data\data.backup.csv` или git).
2. Запустите импорт + `build_json`.
3. Проверьте `git diff data/data.csv`.
4. Верните потерянное: синонимы `canonical_key`, ручное дробление продуктов, удалённый мусор.

У свежеимпортированных строк `canonical_key` пустой. Чтобы вернуть синонимы: сопоставьте строки по `condition_key`, вставьте прежние `canonical_key`, снова запустите `build_json`.

## Правка CSV и сборка JSON

Редактируйте `data/data.csv` в Excel, LibreOffice или текстовом редакторе. Сохраняйте как **UTF-8** (в файле есть BOM; Python читает через `utf-8-sig`).

### Добавить связь

Добавьте строку минимум с полями:

- `category`, `product`, `polarity` (`recommend` или `avoid`), `condition`

`condition_key` можно оставить пустым (пересчитается). `canonical_key` заполняйте только если строка — синоним другого условия. `source_table` / `source_row` — по желанию (трассировка).

### Изменить / обновить строку

- Исправьте опечатки в `product`, `category` или `condition`.
- При смене текста условия можно очистить `condition_key` — он пересчитается.
- **Синонимы:** в вариантной строке укажите `canonical_key` = **нормализованный ключ основного условия** (обычно скопируйте `condition_key` основной строки). Текст варианта станет алиасом в поиске UI. У основной строки `canonical_key` оставьте пустым.
- **Разделить продукт:** продублируйте строку(и) и задайте разный `product`.
- **Разделить несколько условий:** замените одну строку несколькими — по одному условию.

### Удалить строку

Удалите строку в CSV. Строки с пустым `product` или `condition`, либо с `polarity` не из `recommend` / `avoid`, сборщик игнорирует.

### Преобразовать CSV → JSON

После любой правки CSV:

```bash
python -m scripts.build_json
```

С путями по желанию:

```bash
python -m scripts.build_json --csv data/data.csv --out data/data.json
```

Обновите UI (или снова **Загрузить данные**), чтобы подтянуть новый JSON.

## Формат CSV

Одна строка = одна связь: продукт + категория + полярность + одно условие.

| Колонка | Обязательно | Смысл |
|---------|-------------|--------|
| `category` | да | Заголовок таблицы из Word (напр. `Напиток`, `Суп`, `Орех`) |
| `product` | да | Название продукта (колонка 1 Word) |
| `polarity` | да | `recommend` (кол. 2) или `avoid` (кол. 3) |
| `condition` | да | Текст условия, как в UI |
| `condition_key` | нет | Нормализованный ключ `condition`; если пусто — пересчитывается |
| `canonical_key` | нет | Если задан — строка является синонимом условия с этим ключом |
| `source_table` | нет | Номер таблицы Word (с 1) |
| `source_row` | нет | Номер строки Word (с 1) |

**Нормализация** ключей: Unicode NFKC, нижний регистр, `ё`→`е`, сжатие пробелов, срез хвостовой пунктуации.

**Поведение сборщика:**

- Одинаковый `condition_key` → одно условие в JSON (алиасы сливаются).
- Одинаковые связи product / category / polarity дедуплицируются.
- Поиск в UI идёт по отображаемому тексту, ключу и алиасам.

Пример (заголовок + две строки):

```csv
category,product,polarity,condition,condition_key,canonical_key,source_table,source_row
Суп,Борщ,avoid,Луна в напряжённом аспекте к Марсу,,,3,2
Суп,Борщ,recommend,Луна в гармоничном аспекте к Марсу,,,3,2
```

## Обзор интерфейса

Левая панель:

- **Данные** — по умолчанию `data/data.json` (автозагрузка при локальном сервере; **Загрузить по умолчанию** перезагружает). **Другой файл (не по умолчанию)** — только если нужен нестандартный JSON (обязательно на `file://`).
- **Таблица** — *Все продукты* или *Только совпадения*
- **Сохранить результаты (Excel)** — скачать видимую таблицу как `.xlsx`

Основная область:

- Фильтр категории
- Два списка условий: **Рекомендуется** / **Не рекомендуется** (поиск, микрофон в Chrome, постранично)
- Таблица результатов с цветными галочками
- Строка статуса со счётчиками

## Известные особенности

- **`Продукт` и `продукт`:** два написания в Word дают две категории; унифицируйте в CSV и пересоберите (повторный импорт вернёт разделение).
- **Заглушка `Нет`:** импортируется как обычное условие; удалите такие строки CSV, если это шум.
- **Нумерация внутри строки** (например `Если …, 2. Если …`) не делится автоматически — правьте CSV.
- **`file://`:** используйте **Загрузить данные**.
- **Повторный импорт затирает** все ручные правки CSV.
- `Formulas.doc` может быть вне git; извлечения `_formulas_*` в `.gitignore`.
